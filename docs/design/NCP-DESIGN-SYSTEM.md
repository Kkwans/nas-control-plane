# NCP 设计系统

## 2026-07-26 控制台视觉基线

- 画布使用 `#F7F9FC`，主表面保持白色，品牌蓝使用 `#3474D4`；正文、次级和辅助文字必须形成稳定的三级对比。
- 侧栏选中态使用完整、对称的圆角浅蓝块、细边框与轻阴影。任何页面和资源行均禁止使用左侧单边强调条。
- 状态标签必须按内容宽度收缩，不得撑满单元格；状态、容器数、端口、级别和操作列居中，其余文字列左对齐。
- 资源表格使用整行浅色悬停和 160–200ms 过渡；操作表头与按钮严格对齐，所有单元格垂直居中。
- 页面加载使用与最终内容同构的骨架屏；已有数据时禁止同时显示骨架，切换筛选时保留现有内容并局部加载。
- 远程数据在 180ms 内返回时不展示骨架；超过阈值后，骨架与终态容器必须保持同一高度，避免页面闪烁。
- 可排序表头必须同时表达当前排序列和升降方向，未激活列只显示低对比双向提示。
- 品牌 Logo、Favicon 和用户上传图标默认保持透明背景，不额外包裹有色底板。
- 信息面板避免“卡片套卡片”。只有真正独立的资源、能力或快捷入口使用卡片，普通字段优先使用留白、分隔线和背景层级。
- 桌面端以 1440px 为基准；1024px 调整列宽和面板层级；390px 使用汉堡菜单、单列资源行和全屏抽屉。
- 动效只表达状态变化、交互反馈和层级转换，并遵守 `prefers-reduced-motion`。

## 目的

NCP 不是通用后台模板。它应像一块安静、可靠的系统仪表：让操作者先看见事实、状态和下一步，而不是被装饰性视觉干扰。

当前设计系统约束所有管理页面。NCP 是高频运维工作台，不是营销落地页，也不是展示型数据大屏。

## 2026-07-23 高密度管理端规范

- 页面顶部只保留一行标题、实时状态、筛选和主要操作；禁止宣传口号、英文装饰标签和大段开发者说明。
- 桌面侧栏按“总览、服务入口、Docker 管理、数据库、监控、日志中心、终端、系统设置”组织；未实现项必须标记待接入。
- 多资源场景优先表格和紧凑列表。项目卡只有在“打开服务入口”场景使用，并在 1440px 下至少支持三列。
- 品牌与普通标题使用中文；Docker、Compose、CPU、RAM、IP、API 等专业术语可保留。
- 图标操作必须提供中文 Tooltip 和可访问名称，点击区域至少 44×44px。
- 首次进入自动加载；登录期间保持 SSE 实时连接，断线后自动重连并退回轮询。
- 小于 768px 时桌面侧栏必须切换为汉堡按钮与侧滑导航，禁止横向压缩主菜单。
- 服务与 Docker 项目必须提供详情路径；桌面使用侧边抽屉，手机使用全屏抽屉。

## 2026-07-23 默认浅色主题（当前生效）

本节覆盖此前以深色画布为默认值的视觉方向。NCP 现在以浅白、现代且克制的控制台作为默认主题：

- 画布使用暖白与低饱和蓝灰渐层，内容承载面保持纯白；不使用大面积高饱和渐变。
- 主色为钴蓝，健康态使用青绿，警告使用暖琥珀，风险使用柔红；颜色始终与文本状态共同出现。
- 面板使用 10–14px 圆角、细边框和克制阴影；数据表与工具栏避免大圆角和漂浮卡片感。
- 字体继续使用 Manrope Variable 与 JetBrains Mono Variable；标题强调层级，指标和运行时信息保持等宽可读。
- 页面默认只呈现 Root Agent 的真实响应。服务尚未部署、会话未建立或采集失败时，展示明确的登录/离线/降级状态，不提供伪造的实时样本。

## 视觉方向：精密工具台

- 浅灰蓝画布与纯白结构面形成清晰层级，深海军蓝保证正文可读性，钴蓝只强调当前导航和主要操作。
- 健康态使用青绿，警告使用暖琥珀，风险使用柔红；状态颜色始终与图标或中文文本共同出现。
- 面板使用 8–16px 统一圆角、细边框和低对比阴影；悬停只轻微抬升 2px，不产生布局位移。
- 数据数字使用 JetBrains Mono，正文与中文标题使用 Manrope、苹方或微软雅黑 UI 的回退组合。
- 图标统一使用 Lucide SVG 的约 1.8px 线条，不以 emoji 或不同风格图形表达结构性含义。

## Token

| 角色 | Token | 用途 |
|---|---|---|
| 页面画布 | `--ncp-canvas` | 主背景与长时间浏览场景 |
| 基础面板 | `--ncp-surface` | 卡片、分区和容器 |
| 主文字 | `--ncp-text` | 标题、关键数值 |
| 次文字 | `--ncp-text-muted` | 描述和解释 |
| 已核验 | `--ncp-primary` | 正常、完成、可信通道 |
| 中性数据 | `--ncp-info` | 网络、辅助指标 |
| 待观察 | `--ncp-warning` | 未验证、需注意 |
| 风险 | `--ncp-danger` | 明确异常与危险操作 |

间距使用 4px / 8px 倍数；页面外边距在移动端为 14px、桌面端在 18px 至 34px 间响应式增长。所有可触达元素最小尺寸为 44px；小于 12px 的字体只允许用于非关键机器标识，普通说明与状态标签不得使用过小灰字。

## 状态语言

| 状态 | 标签 | 语义 |
|---|---|---|
| `healthy` | 已核验 / 运行稳定 | 有实机或测试证据支持 |
| `degraded` | Docker 不可用 | 功能降级但页面保留可读基础信息 |
| `attention` | 需要关注 | 已发现可解释的资源压力或风险 |
| `pending` | 待验证 | 未实现或未在 NAS 上验证，不能伪装为线上状态 |

颜色不是唯一信号：每个状态标签同时带有文字和圆点。

## 数据连接状态

- 页面启动时并发请求系统摘要、Docker 清单和能力信息；成功后顶部显示实时或轮询更新状态。
- Server 或 Agent 暂不可用时，界面保留最后一次真实数据并明确标注离线或降级，不展示演示数据。
- 网络、代理或响应格式异常不得直接抛到页面；前端只消费稳定错误码，避免泄露底层实现文本。

## 组件规则

- `AppShell` 固定导航位置与层级，所有页面共享同一设备定位、实时连接状态和键盘跳转入口。
- `MetricCard` 只呈现一个主数字和一个解释；不得在同一卡片塞入多个同等重要的指标。
- `StatusPill` 只表达当前状态，不能作为主要操作按钮。
- `WorkspaceHeader` 统一页面标题、实时摘要、搜索、筛选和操作，不允许使用固定大高度制造首屏空白。
- `ProjectDetailDrawer` 统一项目、容器、端口与运维操作，并使用 URL 查询参数保存详情上下文。
- 图表必须有文字标题、单位、图例、交互 Tooltip 和屏幕阅读器可读摘要；数据不足时显示采样进度。
- 所有趋势只能来自当前会话收到的真实快照，不构造随机、固定或平滑伪数据。

## 动效与可访问性

- 页面进入使用 420ms 内的轻微上移与淡入，列表按 55ms 阶梯出现；悬停只使用 `transform`、颜色和阴影，不触发布局位移。
- 动效只用于表达页面进入、可点击反馈和在线信号，不得使用连续装饰动画抢占注意力。
- `prefers-reduced-motion` 下全局关闭非必要动画和过渡。
- 所有交互元素保留可见焦点环；提供“跳到主要内容”链接，路由切换后将焦点移至主内容区。
- 桌面端使用侧栏，小于 768px 使用汉堡按钮和带遮罩的侧滑导航；列表在手机端转换为卡片，不产生页面级横向滚动。

## 后续页面验收

新页面交付前至少完成 `pnpm run typecheck` 和 `pnpm run build`；自动化测试按当前 OpenSpec 任务决定，不再作为所有切片的固定前置条件。
