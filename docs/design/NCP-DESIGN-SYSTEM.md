# NCP 设计系统

## 目的

NCP 不是通用后台模板。它应像一块安静、可靠的系统仪表：让操作者先看见事实、状态和下一步，而不是被装饰性视觉干扰。

当前设计系统约束所有管理页面。NCP 是高频运维工作台，不是营销落地页，也不是展示型数据大屏。

## 2026-07-23 高密度管理端规范

- 页面顶部只保留一行标题、实时状态、筛选和主要操作；禁止宣传口号、英文装饰标签和大段开发者说明。
- 桌面侧栏按“总览、服务入口、Docker 管理、数据库、监控、日志中心、终端、系统设置”组织；未实现项必须标记待接入。
- 多资源场景优先表格和紧凑列表。项目卡只有在“打开服务入口”场景使用，并在 1440px 下至少支持三列。
- 品牌与普通标题使用中文；Docker、Compose、CPU、RAM、IP、API 等专业术语可保留。
- 图标操作必须提供中文 Tooltip 和可访问名称，点击区域至少 40×40px。
- 首次进入自动加载；登录期间保持 SSE 实时连接，断线后自动重连并退回轮询。

## 2026-07-23 默认浅色主题（当前生效）

本节覆盖此前以深色画布为默认值的视觉方向。NCP 现在以浅白、现代且克制的控制台作为默认主题：

- 画布使用暖白与低饱和蓝灰渐层，内容承载面保持纯白；不使用大面积高饱和渐变。
- 主色为钴蓝，健康态使用青绿，警告使用暖琥珀，风险使用柔红；颜色始终与文本状态共同出现。
- 面板使用 10–14px 圆角、细边框和克制阴影；数据表与工具栏避免大圆角和漂浮卡片感。
- 字体继续使用 Manrope Variable 与 JetBrains Mono Variable；标题强调层级，指标和运行时信息保持等宽可读。
- 页面默认只呈现 Root Agent 的真实响应。服务尚未部署、会话未建立或采集失败时，展示明确的登录/离线/降级状态，不提供伪造的实时样本。

## 视觉方向：Quiet System Instrument

- 深色石墨画布承载长期观察场景，避免纯黑造成视觉疲劳。
- 海松绿代表“已核验 / 正常”，冷蓝用于中性数据，暖金用于“待验证 / 需观察”，柔红只表示需要处理的风险。
- 面板使用 14px 圆角和低对比描边；仅状态标签使用完全圆角，避免“所有元素都是药丸”的模板感。
- 数据数字使用等宽字体，正文与标题使用 Manrope Variable，保持阅读节奏与数据稳定性。
- 图标统一使用 Lucide SVG 的约 1.75px 线条，不以 emoji 或不同风格的图形表达结构性含义。

## Token

| 角色 | Token | 用途 |
|---|---|---|
| 页面画布 | `--ncp-canvas` | 主背景与长时间浏览场景 |
| 基础面板 | `--ncp-surface` | 卡片、分区和容器 |
| 主文字 | `--ncp-text` | 标题、关键数值 |
| 次文字 | `--ncp-text-muted` | 描述和解释 |
| 已核验 | `--ncp-primary` | 正常、完成、可信通道 |
| 中性数据 | `--ncp-info` | 网络、辅助指标 |
| 待观察 | `--ncp-warning` | 未验证、需注意 |
| 风险 | `--ncp-danger` | 明确异常与危险操作 |

间距使用 4px / 8px 倍数；页面外边距在移动端为 18px、桌面端在 24px 至 54px 间响应式增长。可触达元素最小高度为 40px，图标型导航在小屏幕保持 44px 点击区域。

## 状态语言

| 状态 | 标签 | 语义 |
|---|---|---|
| `healthy` | 已核验 / 运行稳定 | 有实机或测试证据支持 |
| `degraded` | Docker 不可用 | 功能降级但页面保留可读基础信息 |
| `attention` | 需要关注 | 已发现可解释的资源压力或风险 |
| `pending` | 待验证 | 未实现或未在 NAS 上验证，不能伪装为线上状态 |

颜色不是唯一信号：每个状态标签同时带有文字和圆点。

## 数据连接状态

- 页面启动时请求 `/api/v1/system/capabilities`；成功后顶部设备名与状态切换为“已连接 Agent”。
- Server 或 Agent 暂不可用时，界面保留为“数据演示模式”，并继续展示明确标注的预览内容。
- 网络、代理或响应格式异常不得直接抛到页面；前端只消费稳定错误码，避免泄露底层实现文本。

## 组件规则

- `AppShell` 固定导航位置与层级，所有页面共享同一设备定位、实时连接状态和键盘跳转入口。
- `MetricCard` 只呈现一个主数字和一个解释；不得在同一卡片塞入多个同等重要的指标。
- `StatusPill` 只表达当前状态，不能作为主要操作按钮。
- 图表必须有文字标题、当前值和屏幕阅读器可读的采样列表；不能只依赖颜色判断趋势。
- 真实数据未接入时必须显式显示“数据演示模式”或“待验证”，不构造伪实时状态。

## 动效与可访问性

- 页面进入使用 420ms 内的轻微上移与淡入，列表按 55ms 阶梯出现；悬停只使用 `transform`、颜色和阴影，不触发布局位移。
- 动效只用于表达页面进入、可点击反馈和在线信号，不得使用连续装饰动画抢占注意力。
- `prefers-reduced-motion` 下全局关闭非必要动画和过渡。
- 所有交互元素保留可见焦点环；提供“跳到主要内容”链接，路由切换后将焦点移至主内容区。
- 桌面端使用侧栏，小屏端将导航压缩为带标签语义的图标按钮；不产生横向滚动。

## 后续页面验收

新页面交付前至少完成 `pnpm run typecheck` 和 `pnpm run build`；自动化测试按当前 OpenSpec 任务决定，不再作为所有切片的固定前置条件。
