# NCP 故障隔离与恢复

## 边界与恢复行为

- Root Agent 是核心权限边界；不通过 Server 直接访问 Docker Socket 绕过它。
- Mihomo 为可选模块。配置缺失、格式错误或控制器配置错误只影响代理 RPC，不再阻断 Agent 启动及其他模块。
- 初始化失败后，下一个代理请求触发恢复检查；采用互斥与 1、2、4、8、16、32、60 秒的退避，上限一分钟，不开后台重试线程。冷却期间立即返回稳定不可用错误，不重复读取配置或刷日志。
- 配置恢复后在下一次允许的请求中重新初始化；成功实例复用。已初始化的控制器网络故障由后续请求重新探测，不通过重启整个 Agent 处理。
- 没有启用代理的部署保持原有行为，不主动发现或连接其他代理端点。
- 初始化失败日志只含模块名、稳定错误码和重试间隔，不打印配置内容、令牌或底层错误文本。

## 存活与就绪分离

- `/healthz`：HTTP Server 存活检查，依赖中断不改变其 200 语义。
- `/readyz`：依次检查 Agent RPC、Docker 实时清单、已配置认证服务的数据库读能力。共享超时不超过三秒；成功返回 200，依赖中断/超时返回 503。
- 就绪响应只包含模块状态，不含容器清单、宿主机路径、账号或底层错误；设置 `Cache-Control: no-store`。
- Nginx 显式代理 `/readyz`，不能用 SPA HTML 兜底假报成功。Server 容器健康检查使用就绪端点；Console 存活检查保持独立。
- Docker 的 `unhealthy` 状态是可观察信号，不等同于自动重启。禁止为了恢复控制台而自动重启 Docker Engine 或受管理业务容器。

## 进程恢复与运行配置

- systemd 只对 Agent 自身的异常退出重启；重试间隔为 30 秒，避免三秒一次的持续重启和日志风暴。
- `RuntimeDirectoryPreserve=yes` 必须保留，避免容器继续挂载旧 `/run/ncp` 目录。
- 当前 Mihomo AIO 配置入口为 `/volume2/DockerProject/mihomo/data/active.yaml`。迁移配置时同步核对 `NCP_MIHOMO_CONFIG_PATH`，不要重新创建退役路径或复制一套长期配置。
- 真实运行路径可通过 systemd drop-in 覆盖；没有把运行时令牌写入仓库。

## 验证与回滚

回归测试覆盖缺失代理配置时核心 RPC 可用、配置恢复、并发限频、退避上限、取消、日志脱敏，以及核心依赖失效/恢复和就绪超时。故障注入必须使用隔离文件和 Socket，不停止生产 Docker 或破坏真实代理配置。

发布前备份现有 Agent、镜像标识和实际部署配置；从已验证、已推送 SHA 的干净源码构建。回滚恢复旧二进制和镜像，保留已经核实有效的配置路径。此机制不包含跨主机高可用、数据库灾备或磁盘损坏恢复；这些需要独立的备份目标、保留策略和恢复演练。
