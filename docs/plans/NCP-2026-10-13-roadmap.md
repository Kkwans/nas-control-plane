# NCP 持续改进计划与技术方案

更新：2026-10-13。审计基线：`5b81557068a9a44cae3b06ac6207438a399e8ef7`。开发分支：`dot/ncp-modernization`。

## 目标与交付原则

保留已有 Go Root Agent → 非特权 Server → Vue 控制台架构与真实管理能力，先解决数据正确性、恢复和操作可信度，再完善高密度 UI 与功能。不是重写项目，也不是把 NAS 改成纯演示。Linux 云环境用于编译、隔离测试和 fixture 浏览器验收；systemd、Docker Socket、真实数据库、NAS硬件能力必须分别确认，不能因为操作系统相同就视为具备。禁止触碰用户 NAS、部署、发布、改生产或安全凭据；源代码 push 不等于部署。

用户已授权按模块测试、中文 commit（标题+正文）及 push；不强推、不合并 main、不自动发布 tag。每次执行先检查分支/dirty/远端/已有工作，避免重叠。无进展时选择未阻塞切片继续，不能把所有时间耗在一个环境问题上。OpenSpec 不启用。

## 产品方向

1. 可靠操作：每次操作始终知道“哪个资源、提交了什么、是否实际完成、失败后能做什么”。
2. 信息结构：沿用总览/站点/Docker/数据库/监控/日志/终端/系统/用户/设置；不堆新导航。通用任务中心先收敛现有Job，再扩展耗时操作。
3. 监控可信：采集时钟属于服务生命周期，浏览器只订阅；无页面时也应有历史，数据过期不可显示成健康。
4. 精致工具台：保留浅灰蓝画布、白色结构面和品牌蓝；清晰状态、紧凑表格、中文排版、可读数字优先。图标保持Lucide语义映射，不为“高级感”增加装饰图标。
5. 动效用于抽屉、加载切换与操作反馈，避免连续装饰动画；遵循减少动态效果。首次加载、旧数据刷新、失败、真空态分别呈现。

## 核心技术方案

### Job隔离与状态

第一步不改变外部API，解决内部可变快照泄漏：所有离开锁域的对象都由深拷贝生成，JSON序列化只能读取自有快照。随后单独推进持久化顺序和状态机，避免把紧急并发修复和全量队列重构绑在一起。更新包含run identity与revision；完成/取消/失败终态单调；删除要阻止迟到写入复活。不能用锁住整个registry执行不可控数据库IO的方式换取表面正确。

### Vue请求与提交一致性

区分读取取消、UI观察失效与服务端Job取消。每个资源会话捕获不可变key（项目/来源/容器/筛选）和generation；只有当前代次可落UI状态，finally也只清理自己的busy。写操作发送冻结payload；成功只标记实际提交版本，用户后续编辑保留dirty。复用已有RequestSequenceGate和sessionLifecycle，避免每页另造互斥规则。

### 设计系统与UI验收

沿用现有设计文档的最新规则，清理其过时OpenSpec验收描述。基础色#F7F9FC、白表面、品牌#3474D4及既有状态Token；字体尊重用户选择，中文fallback与实际family名实测。Lucide规范以现有约1.8px描边及明确可访问名为基础，危险动作有文字和对象。数据表对齐、密度和触控尺寸由Token控制；不一次性重写所有CSS。所有视觉判断记录截图来源、viewport、fixture/真实API、精确SHA。

### 验证分层

- L1 静态：Go vet/build、Vue typecheck/lint、OpenAPI同步检查。
- L2 纯测试：Vitest、Go单元、Job race与可控延迟/故障fake。
- L3 浏览器：真实Chromium+mock API证明前端交互、键盘、截图、axe，不证明NAS管理实际成功。
- L4 隔离集成：临时文件/SQLite/Unix socket/受控子进程，明确不访问真实Docker/数据库/主机变更。
- L5 NAS实机：当前未授权操作；只有另行授权后由指定环境执行。

## 持续工作与文档维护

每20分钟核对真实diff/提交/工作状态；主代理保持跨模块协调。后端、前端行为、视觉验收可并行，公共API/共享文件由主代理统筹。单模块门槛失败时记录失败而非删除测试，推进独立模块。模块交付记录：变更、测试命令与结果、commit、远端确认、CI、未验证项。重大协议/迁移单独ADR；不要为每个小修复生成重复流程文档。
