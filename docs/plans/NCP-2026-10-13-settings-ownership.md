# 设置加载基线与保存归属

日期：2026-10-13。状态：已实现并通过组件/store 隔离验证；独立复核已完成，待提交与 CI。本切片只处理设置页及 system store 的加载、编辑预览、自动保存和认证归属；不调用真实设置 API，不修改 NAS、账号或认证协议。响应字段解码单独安排。

## 已确认的问题与范围

1. **初始基线缺失导致完整覆盖。** `App.vue:68–78` 异步读取偏好，读取失败被吞掉；设置页仍可从 store 默认值创建草稿。`SettingsView.vue:89–96` 在发生编辑后拒绝读取结果，`104–106` 保存整个草稿。后端 `controlstore/store.go:279–293` 更新全部字段，因此在首次读取完成前或失败后修改一个字段，会把其他已保存字段覆盖为默认值。
2. **延迟保存重新取得认证归属。** `SettingsView.vue:117–126` 会在旧保存失败后继续调度较新草稿，`226–228` 在卸载时尝试 flush；没有固定会话检查。`App.vue:106–112` 先失效会话，`system.ts:173–176` 却在下一次保存开始时才捕获当前会话，旧编辑器可能借用替换后的认证上下文发起 PUT。后端偏好确实按用户隔离：`httpapi/preferences.go:23,40` 传入当前 principal ID，存储查询和 upsert 按 `user_id` 执行；只有另一个用户在延迟发送前完成登录时，才构成写入另一个账号偏好的具体情形。
3. **旧保存响应覆盖新预览。** 设置页先预览草稿 B，保存 A 返回后 `system.ts:175–180` 无条件应用 A。页面虽然继续保留 B 并调度保存，却没有恢复 B 的视觉预览；B 保存失败时，字号、密度或字体与控件值持续不一致。

以上为源码因果分析，尚无本轮浏览器复现。现有全局请求取消保护正在进行的旧请求，不保护失效后重新创建的请求。

## 实现约束

- **可信初始基线。** 提供偏好的未加载、加载中、已加载和失败状态。首次加载成功前禁用编辑、恢复默认与保存；失败显示明确说明和只读重试。默认值仅用于启动外观，不冒充已读取的保存基线。后台重读失败保留先前可信值及错误状态，不把草稿换回默认值。
- **固定会话归属。** 编辑器及其保存队列固定捕获创建时的认证上下文。发送前、响应后、catch/finally 和后续定时调度均验证归属。会话失效后清理待发送队列和定时器，不发起新 PUT，不重放写入，也不更新替换会话的 store 或 DOM。取消观察不等于撤销服务端已接收的写入。
- **保留普通导航的保存意图。** 同一有效会话内离开设置页时，允许已明确编辑的待保存快照继续 flush，保留既有产品行为；队列不得依赖已卸载页面的 UI 状态。若正在保存 A，后续 B 只在同一有效会话内按顺序提交。返回设置页时应复用或协调该队列，不能让离开的旧编辑器与新编辑器并行覆盖彼此。退出登录与普通路由离开必须分开处理。
- **读取与写入排序。** 初始读取可去重；迟到 GET 不得覆盖较新的已提交 PUT 或活动草稿。读取 generation、已保存快照、当前编辑 revision 和保存中快照分别拥有明确归属。不要只加 latest-wins 响应检查而允许多个全量 PUT 无序落库。
- **预览与持久化分离。** 保存 A 成功只推进 A 的持久化基线。当前活动草稿 B 保持 dirty 和预览，失败也不回退；无活动草稿时才应用已接受的持久化外观。卸载后的旧预览不得覆盖新编辑器，会话结束恢复当前会话的正确外观。
- **加载不是编辑。** 基线 hydration 不触发自动保存或递增用户编辑 revision；Vue 异步 watcher 的抑制范围必须覆盖真正执行的回调，不能只在同步赋值前后切换布尔值。
- **有限范围。** 保持现有 API 和后端用户隔离；不扩展列表偏好、字体下载机制或完整响应解码。读失败可重试；未知写结果不得声称一定未保存或自动重放同一操作。

## 隔离验收矩阵

| 情形 | 必须成立 |
|---|---|
| 初始 GET 延迟，保存值包含自定义字体/顺序 | 控件不可编辑、无 PUT；成功后完整 hydration，无多余保存 |
| 初始 GET 失败后重试成功 | 显示失败与重试；失败期间无默认值覆盖；后续只改一项仍保留其他字段 |
| 旧 GET 在新 PUT 成功后返回 | 不回退已保存状态、刷新频率或视觉预览 |
| 保存 A 中继续编辑 B，A 成功，B 失败 | 持久化基线为 A，草稿及预览为 B，dirty/失败/重试可见 |
| debounce 未触发即失效会话 | 定时器不再发送 PUT，不更新清理后的 store/DOM |
| A 保存中、B 待保存，失效后 A 拒绝或迟到成功 | 无后续 B PUT、无旧 finally 重建计时器、无旧状态回写 |
| 上述失效后立即 beginSession | 旧编辑器不得借用新 session；所有新请求只归新编辑器 |
| 有效会话内离开页面，含 A 中/B 待保存 | 合法快照串行 flush；不访问已卸载 UI；不因普通导航丢弃意图 |
| 同会话离开后迅速重开并编辑 C | A/B/C 归属与写入顺序明确，旧响应不覆盖 C 或错误宣称已保存 |
| 同会话保存结束前再退出登录 | 已发送操作结果不夸大；尚未发送的队列立即失效 |

先用 deferred Promise、fake timer、mock API 与 DOM 样式断言覆盖实际组件/store 路径，再运行单元、类型检查及生产构建。浏览器 fixture 仅验证加载/失败/保存状态和交互，不证明真实 NAS 写入成功。完成后补充精确测试结果、提交与 CI 证据，再更新路线图。

## 实现与隔离证据（2026-10-13）

- `frontend/src/stores/preferences.ts` 保存可信加载状态、持久化基线及最新草稿；初次 GET 未成功时不接受编辑，读取去重并保留可重试错误。写入开始前或期间发出的 GET 不得取代较新的保存基线。
- 保存队列属于 system store，编辑权使用独立 token，同一会话普通导航保留串行 flush，重开页面继承最新草稿。会话 signal 失效立即清除计时器、待保存快照及编辑权；异步 continuation 另以 session 和 epoch 检查阻止迟到副作用。
- PUT A 成功只推进持久化基线；仍活动的 B 预览不回退。没有活动编辑器时使用持久化外观。成功响应字段不合法的未知写结果暂停自动队列，先只读核实，再由用户确认保存仍有差异的草稿；核实失败不能恢复写入。
- `SettingsView.vue` 使用同步 watcher 和 hydration guard，读取不计为编辑；未读取时禁用所有控件、重置及拖动。移除“设备未检测到字体就改为 system”的挂载副作用，以免静默改写已保存的设备字体偏好。
- 新增 `SettingsView.test.ts` 17 个 mock/deferred/fake-timer 用例，直接挂载真实组件和 Pinia store，覆盖首次失败/重试、GET 去重与跨会话迟到、GET/PUT 排序、A/B 预览与失败、退出前 debounce、旧 A 成败与新会话、同会话路由 flush/重开 A-B-C 串行，以及未知写结果的只读核实与明确再保存。
- 当前已执行：17 个新增用例通过；前端 lint、类型检查及生产构建通过，最大 chunk 518.0 KiB，低于 540 KiB 预算（保留构建器通用 500 kB 提示）。全量前端单元 66 个文件、1,175 个用例通过；提交/CI 由最终冻结快照复核后补记。
- 以上仅使用 mock API 和 jsdom；没有调用真实设置 GET/PUT、启动浏览器或监听端口，没有修改真实 NAS、账号偏好或用户电脑。取消只撤销客户端后续处理，不能保证服务端撤销已经接收的操作。
