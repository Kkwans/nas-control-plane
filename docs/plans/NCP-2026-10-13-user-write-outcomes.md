# M19-C 账号写入结果边界

日期：2026-10-13。范围仅前端账号创建、状态、改密与删除；不改变认证、密码规则、凭据、数据库或部署。

## 已确认问题与接口合同

通用 transport 把 200 `{}` 当成改密/删除成功，账号返回未校验；丢失响应后解锁原密码表单可重复提交。创建 INSERT 后获取 ID、状态提交后读取账号均可能失败，因此普通 500 及状态的账号不存在 404 不能证明未执行。

专用 transport 在 fetch 前构造固定请求，禁止自动跳转重放。创建仅接受 201 和完整账号（匹配去首尾空白的用户名、Root、未禁用）；状态仅接受 200 和完整账号（匹配 ID 与 disabled）；改密/删除仅接受 204。读取与写入共用账号解析器。其余成功、坏响应、读取中断、传输失败或未证明安全的 HTTP 错误均为结果未知。只有按操作核实的状态/稳定错误码配对属于明确拒绝；返回固定中文文案，不保存或暴露密码、原始响应、异常 cause。

## UI 恢复与真实管理能力

等待提交与未知尝试分开；未知记录只含操作、账号 ID/用户名，不含密码、提交载荷或完整账号对象；不保存时间/状态意图。创建锁身份采用 Go 空白归一化及 SQLite NOCASE 的 ASCII 大小写折叠，显示与成功响应关联仍保留服务端用户名大小写。关闭或重开弹窗不清未知，旧弹窗未知也须在页面可见。未知使早先列表读取失效；清除对应敏感草稿，不显示成功、不自动写重试、不在自己改密未知后执行成功重载。

状态与删除可通过后发、完整校验 GET 显示当前账号状态/缺失；只证明观察时的状态，不冒称原请求成功。密码与创建不能靠同名、时间戳或空列表确认密码/归属；禁止登录探测和补偿删除。核对中保持只读；恢复新的明确操作须使用新确认，不复用未知载荷。

阻断按当前页面会话及目标/用户名限定，其他账号和非冲突管理操作继续可用，不把整个 Root 控制台永久锁死。对无法读取核实的创建/密码，未知说明必须清楚告知本会话不重放；用户可以自行结束会话、重新登录后重新评估并发起新的管理意图，这不表示旧尝试已核实。不持久化密码，也不自动开启重登录或新凭据写入。首片仅为页面生命周期内记录：弹窗关闭/重开不清锁；页面卸载或会话结束清理内存，不跨路由/刷新持久化。不把重新进入页面视作核实或保证请求没有执行；恢复说明必须提示人工重新评估，不能鼓励刷新后直接重发。可靠跨会话归属/自动恢复需要另行设计请求回执协议，本片不实现。

## 验证与停止条件

仅伪造数据、纯 transport/视图测试：精确成功合同、错目标、坏 body、断网/跳转、拒绝配对、提交快照、旧弹窗、重复点击、只读核对、会话失效、无凭据泄漏。API 与 UI 分开实施后运行相关测试、完整单元、lint、类型和生产构建。无需也不允许用真实账号验证；不启动服务或浏览器。前端合同与 UI 恢复路径完成并通过静态/纯测试即停止；没有可验证回执时保留明确未知，不循环探测。
