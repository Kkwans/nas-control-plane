# 日志实时流最近 ID 去重预算

## 范围与方案

日志 SSE 原先用单连接 map 记住全部已发送 ID，连接持续期间会无限增长。本次将它替换为私有、零值可用的最近 ID FIFO 集合；不改变日志查询、SSE 数据结构、心跳、不可用事件或取消处理，不涉及 NAS、真实 Agent、监听器或部署。

- 每连接最多保留 2048 个精确 ID，ID 内容合计最多 256 KiB（按字符串字节数计）。不引入哈希替代 ID，也不更改现有容器日志 ID 生成方式。
- 新 ID 入队前按最早进入顺序逐个淘汰，直到数量和字节预算都满足。重复 ID 只被抑制，不刷新顺序。淘汰后再次出现的旧 ID 可以重新发送。
- 单个 ID 恰好 256 KiB 可保留；超过 256 KiB 则照常发送但不保留、不挤出已有窗口，因此此类 ID 可能重复发送。不会因为去重预算产生新的连接错误。
- 空 ID 保持原有精确匹配行为：首次发送，其后直到淘汰前都抑制；占一个槽位、零内容字节。
- 固定 2048 槽环形数组避免队列底层存储增长；淘汰时删除 map 项并清空数组槽位。用 strings.Clone 复制首次保留的 ID，让集合和队列共用同一份独立 ID，避免子串保留整个上游载荷。不存储日志记录、消息或响应对象。
- 状态仅属于当前连接，由处理流的 goroutine 使用，连接结束自然释放；不同连接不共享去重窗口。

## 兼容性与边界

原有增量记录遍历、NextCursor 与 since 推进位置不变：只有有增量记录时才更新查询游标与时间；重复记录整页仍发送心跳。窗口外记录和超大 ID 允许再次发送，这是有限内存去重的明确取舍。

256 KiB 仅是去重保留 ID 内容的预算，不是整个连接或查询响应的总内存上限。固定数组、map 元数据、查询结果、当前游标、序列化和 SSE 帧另有开销。此切片不提供全局并发配额或帧大小上限。

## 验证

只运行已检查的进程内测试：假 Agent、假 ticker、内存 writer，不启动服务或执行宿主机命令。

- 辅助结构：跨多轮环绕的数量上限、精确字节边界、字节压力批量淘汰、重复不刷新顺序、清空槽位、超大 ID、空 ID、克隆后的底层存储和连接隔离。
- SSE：按每页不超过 200 条填满窗口，验证近期重复心跳、不可用事件、FIFO 淘汰后的重发、超大 ID 重发、空 ID 去重、游标/时间推进、原有帧结构和取消停止 ticker。
