# UI 证据制品有界分片

## 原因与边界

此前单个 fixture UI ZIP 已达到 34,020,460 bytes，超过证据读取工具的 32 MiB 上限。后续 CI 改为最多八个独立制品，名称保留 SHA 与 run attempt，并追加 `-part-N`。不改变 E2E 捕获范围，不绕过原制品下载限制。

- Python 标准库脚本只复制 `test-results/**/ui-captures/*.png` 与 `*-capture-state.json`，沿用隐藏文件排除规则；不包含 trace、认证状态等其他输出。
- 按 test-results 相对路径稳定排序，保留目录及文件原始字节，原始测试结果不移动、不删除。
- 每片文件内容最多 24 MiB；另以每文件 `1024 + 4 × UTF-8 路径字节数` 计入独立的 1 MiB ZIP 元数据预算，防止大量空文件或长路径耗尽余量。为压缩及 ZIP 容器保留充足的 32 MiB 以下余量。
- 单文件超限、超过八片、旧输出目录或白名单文件符号链接会明确失败。符号链接目录不遍历。完整预检后才开始复制，不静默截断证据。
- CI 在 E2E 后以 `always()` 执行测试与准备；只有准备成功且分片存在时，才用官方 `actions/upload-artifact@v4` 分别上传。空源不上传；已声明分片缺失视为错误。原 E2E 失败仍保持失败。

- 覆盖真实 24 MiB 边界、稳定路径顺序与重复结果、全量路径/SHA-256 一致、白名单及隐藏项排除、符号链接、单文件超限、八片与第九片、空文件元数据超限、空源、旧/嵌套目标目录和 GitHub 输出协议。
- 使用已安装的 PyYAML 解析工作流并检查八个上传动作的名称、目录和条件；`git diff --check` 通过。
- 未启动浏览器或监听服务；未安装网络包；未改动 token、权限或部署。
- 本地无当前截图集合，尚未验证本次提交的真实 GitHub 上传及下载 ZIP 大小，需由后续 CI 完成。
