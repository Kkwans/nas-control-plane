# NCP v0.2：Root 控制面 MVP 方向说明

更新时间：2026-07-19
状态：已采纳

## 目的

本说明补充原始 v0.1 Spec，并调整仓库当前实现顺序。NCP 的近期目标不再是继续扩展独立技术 PoC，而是在绿联 NAS 上交付一个可登录、能读取真实状态并管理真实资源的 Root 控制面。

## Root 能力模型

`ncp-agent` 是宿主机原生 root 服务，拥有 NCP 所需的完整能力：

- Docker Engine、Compose 项目、容器、镜像、网络和卷。
- systemd、journald、主机进程、磁盘、网络和实时指标。
- 宿主机与容器 PTY 终端。
- 后续的 Caddy 与数据库备份恢复工具。

`ncp-server` 提供登录、HTTP API、WebSocket、页面静态资源、SQLite 元数据和 Job 协调。它通过 Unix Socket 调用 Agent。这个分层仅用于保持进程职责清晰；登录后的 `root` 角色可使用所有已实现的 Agent 能力，不会因 Server 非 root 而缺少管理权限。

## MVP 登录与权限

第一版只实现一个可登录的 `root` 角色：

- 首次初始化创建 Root 管理员。
- Root 登录后拥有所有已实现的 `system`、`docker`、`services`、`logs`、`terminal` 与 `settings` 能力。
- 不以 Viewer、Operator 等多角色模型阻塞功能交付；细粒度 RBAC 后置。

## 接口原则

Root 控制面必须覆盖真实 NAS 能力，但接口仍按资源域定义：Docker、system、日志、服务、终端与 Compose 各自拥有明确的请求和响应模型。宿主机 Root 终端使用独立 PTY/WebSocket 会话；其他能力使用强类型 RPC 和 API，不以任意字符串命令作为通用产品接口。

## 交付切片

按如下顺序交付可见功能，每完成一个切片立即接入前端并提交：

1. Root Agent 常驻服务、Server-Agent 真实连通和 Root 登录初始化。
2. 系统总览真实数据：主机、CPU、内存、磁盘、网络、Docker 状态。
3. Docker/Compose 自动发现与服务中心真实列表、端口入口。
4. 容器启停重启、日志、实时 stats 与 Job 反馈。
5. 容器终端和宿主机 Root 终端。

## 不再作为 MVP 前置条件

- P0-06 Caddy 运行时 PoC。
- 多用户细粒度 RBAC。
- 数据库管理、恢复、长期指标和在线升级。
- 将所有功能一次性纳入完整 Phase 0 退出条件。

## 当前部署的定位

`nas-control-plane-console` 仅用于承载 Vue SPA 预览。它不是完整 Root 控制面发布包；Root Agent、Server、数据库与真实 API 接通后，将以可复现的原生服务发布方式替代预览部署。

## 2026-07-23 实现状态

- 已完成 Root Agent 的实时系统快照、Docker Engine/容器/Compose 自动发现，以及 Server 对应的只读 HTTP API。
- 已完成 SQLite 一次性 Root 初始化、bcrypt 密码哈希和持久化会话；所有控制面 API 在 Server 配置登录服务时均要求有效 Root 会话。
- 尚未在 NAS 安装 root `ncp-agent` 或正式 `ncp-server` systemd 单元，因此上述能力均已通过本地测试和 ARM64 构建验证，仍待实际服务部署后的端到端验证。
