## Context

NCP 已接入 Root Agent、SSE 和真实 Docker 清单，但当前前端仍以页面内联样式为主，服务入口与 Docker 管理缺少稳定的工作区结构和项目详情路径。实时数据只显示当前值，没有会话内历史；移动端则把桌面侧栏压缩成横向导航，无法承载完整菜单和详情操作。

本轮不增加后端数据模型，优先用现有真实快照、Docker 清单和控制 API 构建完整的前端管理体验。

## Goals / Non-Goals

**Goals:**

- 形成一套适用于总览、服务入口和 Docker 管理的高密度工作区布局。
- 提供可通过 URL 恢复的项目详情抽屉，详情与列表共享真实清单。
- 在 Pinia 中维护最近 60 个实时采样点，为首页提供 CPU、内存、负载和网络吞吐趋势。
- 在 768px 以下使用汉堡按钮和侧滑导航；表格内容转换为卡片，不依赖横向滚动。
- 使用统一语义令牌控制字体、颜色、阴影、圆角、悬停、按压、焦点和 reduced-motion。

**Non-Goals:**

- 不持久化历史指标，不承诺跨会话监控曲线。
- 不新增数据库、镜像、网络和存储卷管理 API。
- 不在本轮实现深色模式。
- 不改变现有容器生命周期与日志接口。

## Decisions

### 使用会话内环形采样而不是新增监控后端

每次成功接收系统快照时，将 CPU、内存、负载、网络累计字节与根据相邻快照计算的网络速率写入最多 60 个采样点。这样能立即提供真实趋势且不扩大后端范围。缺点是刷新页面会清空历史，页面必须明确标注“本次会话”。

### 使用共享项目详情抽屉

服务入口和 Docker 管理共同使用 `ProjectDetailDrawer`。详情通过 `?project=<id>` 写入当前路由，支持刷新恢复和浏览器前进/后退；桌面端为右侧抽屉，手机端为全屏抽屉。容器操作只在 Docker 管理页启用。

### 使用自适应导航而不是缩窄侧栏

桌面保留 232px 固定侧栏；中等屏幕可收窄为图标栏；小于 768px 时侧栏完全移出画布，由顶部 48px 汉堡按钮打开带遮罩的侧滑导航。路由切换、遮罩点击和 Escape 均关闭菜单。

### 图表使用现有 ECharts 依赖

采用折线/面积图显示 CPU 与内存，采用双折线显示网络上下行速率。图表提供 Tooltip、图例、单位、空状态和文本摘要；移动端减少坐标刻度，动画遵循 `prefers-reduced-motion`。

### 设计方向为“精密工具台”

浅灰蓝画布、白色结构面、深海军蓝正文和克制的高饱和蓝作为主操作色。标题使用清晰的中文无衬线层级，数字使用 JetBrains Mono；卡片只使用轻边框和悬停抬升，不使用大面积渐变或装饰空白。

## Risks / Trade-offs

- [会话初期图表采样不足] → 展示采样进度和当前值，至少两个点后再绘制趋势。
- [大量容器导致详情过长] → 抽屉内部使用分区和垂直滚动，操作栏保持可见。
- [移动端管理操作误触] → 所有触控目标至少 44px，危险操作使用明确颜色和 Tooltip/标签。
- [路由查询参数与实时清单短暂不一致] → 找不到项目时关闭详情并移除无效查询参数。
- [ECharts 增加首屏体积] → 图表组件仅在总览路由懒加载时进入对应分包。

## Migration Plan

1. 先提交 OpenSpec 与设计令牌。
2. 实现采样 Store、共享工作区组件、详情抽屉和响应式导航。
3. 重构三个页面并完成类型检查与生产构建。
4. 构建下一规范 ARM64 镜像，增量重建 NCP Server/Console。
5. 若部署异常，将 Compose 镜像切回上一版本并重新构建上一提交的前端 `dist`。
