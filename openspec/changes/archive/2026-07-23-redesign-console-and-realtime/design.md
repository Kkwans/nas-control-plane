## Context

NCP 当前已经具备 Root 登录、主机快照、Docker 清单、容器启停重启和日志尾部读取，但页面仍按早期展示型原型组织：三个一级菜单、巨大标题区、双列项目卡和手动刷新。用户真正需要的是长期运行的中文 NAS 管理工作台，先快速定位资源，再执行操作。

宝塔面板用于参考管理产品的信息组织：固定主导航、模块内部二级导航、列表/表格承载大量资源、主要操作始终可见。NCP 不复用宝塔配色、品牌、组件代码或视觉细节。

## Goals / Non-Goals

**Goals:**

- 首屏直接展示可操作的实时状态，不出现宣传式内容。
- 建立完整产品导航，同时诚实区分“当前可用”和“规格已规划”。
- 将“统一服务入口”与“Docker 技术运维”拆成两个任务模型。
- 使用 HTTP SSE 让页面自动更新，并在断线时自动恢复。
- 用统一 Token、中文文案、列表密度、Tooltip 和操作尺寸约束所有现有页面。

**Non-Goals:**

- 本变更不实现数据库管理、镜像拉取、网络/卷写操作和完整终端 UI。
- 不增加暗色主题。
- 不引入新的前端组件库或复制 BaoTa 代码。
- 不以本轮为名补做大规模测试；只执行类型检查、构建和部署健康检查。

## Decisions

### 1. 桌面运维工作台而非营销型 Dashboard

页面使用 224px 固定侧栏、56px 顶栏和最大化内容区域。页面标题只占一行；状态、筛选、自动更新时间和主要操作与标题同区。资源数量超过四个时优先使用表格或紧凑列表。

替代方案是继续使用大卡片并压缩尺寸，但它仍会把项目状态、路径、端口和操作拆散，扫描效率低。

### 2. 导航按用户任务分层

当前可用一级入口为：总览、服务入口、Docker 管理、系统信息。数据库、监控、日志中心、终端和设置保留在产品导航中并标记“待接入”，点击不会跳转到伪页面。安全中心、WAF、软件商店和多节点不进入当前导航。

### 3. 服务入口与 Docker 管理解耦

服务入口面向“打开应用”，以 3～4 列紧凑入口卡展示项目名、状态和端口；Docker 管理面向“运维资源”，以项目表格和可展开容器行展示镜像、状态、端口、路径、启停、重启和日志。

### 4. SSE 传递失效事件，REST 返回权威快照

新增 `GET /api/v1/system/events`。Server 每 5 秒发送 `snapshot` 事件和时间戳，前端收到后刷新主机与 Docker 快照。SSE 不复制业务数据模型，避免 REST 与流式协议形成两套响应契约。

EventSource 断线由浏览器自动重连；前端同时启用 15 秒降级轮询。刷新采用单飞控制，上一轮未结束时跳过新一轮，避免并发堆积。页面隐藏时停止主动轮询，恢复可见后立即刷新。

### 5. 统一交互标准

- 非专业术语一律中文；Docker、Compose、CPU、RAM、IP、API 等保留。
- 图标操作视觉尺寸 36～40px、点击区域至少 40px，并使用 Element Plus Tooltip。
- 动效只用于路由进入、行展开、加载和状态变化，150～240ms；支持 `prefers-reduced-motion`。
- 数据数值使用等宽字体，正文使用适合中文的系统字体栈，取消英文装饰字体作为页面结构。

## Risks / Trade-offs

- [SSE 仅发送失效事件，仍会产生 REST 请求] → 合并重复的 services 请求，并用单飞与页面可见性控制频率。
- [完整导航中存在未实现模块] → 使用禁用状态和“待接入”Tooltip，不创建空白页面。
- [表格在窄屏上信息过多] → 小于 900px 时切换为紧凑资源块，并将次要列折叠到详情区。
- [部署后旧浏览器缓存静态资源] → Vite 产物使用内容哈希；部署后核对首页资源引用与容器健康状态。

## Migration Plan

1. 先部署兼容旧 REST API 的新前端和 SSE 后端。
2. 新增路由不改变认证 Cookie、SQLite 或 Agent RPC，不需要数据迁移。
3. 构建新的 ARM64 Server 镜像并增量重建 NCP Compose。
4. 若上线失败，将 Compose 镜像标签回退到上一版本，并恢复上一提交的 `frontend/dist`。

## Open Questions

- 数据库、镜像、网络、卷和终端模块分别在后续 OpenSpec change 中实现。
- Docker Engine Events 的 Agent 侧订阅与秒级推送后续替换当前 5 秒 SSE tick。
