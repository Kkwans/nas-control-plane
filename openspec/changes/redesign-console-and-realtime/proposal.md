## Why

当前控制台采用大幅宣传式标题、英文装饰标签和低密度卡片，首屏空间没有用于管理操作；首次进入还依赖手动刷新才能看到数据。这与 NCP 作为“家用 NAS 服务器统一控制面”的产品目标不一致，也让已经接入的真实 Root Agent 能力看起来像静态演示。

## What Changes

- 重构主导航，恢复“总览、服务入口、Docker 管理、数据库、监控、日志、终端、系统设置”的产品信息架构；当前未实现模块明确标记为待接入，不伪装为可用。
- 删除所有页面顶部的宣传式大标题、英文装饰标签和开发者说明，改为紧凑的页面标题、状态、筛选和主要操作区。
- 总览改为高密度运行看板，首屏直接展示主机、CPU、内存、存储、网络、Docker 和服务入口。
- 将服务入口与 Docker 运维分离：服务入口解决统一访问，Docker 管理以项目和容器表格承载状态、端口、日志和生命周期操作。
- 所有非专业术语默认使用中文；保留 Docker、Compose、CPU、IP、API 等约定俗成的技术名称。
- 图标操作使用不小于 40×40px 的点击区域、中文 Tooltip、明确的加载/禁用/危险状态。
- 新增受认证保护的 HTTP SSE 长连接。页面首次进入立即拉取数据，随后由服务端事件触发增量刷新；断线时自动重连并退回低频轮询。
- 更新 NCP 设计系统和项目工作流：后续功能以 OpenSpec 规格、设计、任务、实现、构建、部署的 SDD 流程推进，不再要求测试驱动。

## Capabilities

### New Capabilities

- `console-information-architecture`: 中文优先的控制台导航、页面层级、密度、操作与状态呈现规范。
- `realtime-dashboard`: 首次自动加载、SSE 更新、断线重连和轮询降级规范。
- `docker-operations-workspace`: Docker 项目、容器、端口、日志和生命周期操作的高密度工作台规范。

### Modified Capabilities

无。当前仓库尚未建立 OpenSpec 主规格。

## Impact

- 前端：`AppShell`、路由、Pinia 系统状态、总览、服务入口、Docker 管理和系统信息页面，以及全局设计 Token。
- 后端：新增只读 SSE 事件端点，并同步更新 OpenAPI。
- 文档：更新设计系统、项目约束和阶段进度；BaoTa 仓库仅作为信息架构与交互密度参考，不复制其视觉代码。
- 部署：重新构建 Vue 静态资源和 ARM64 Server 镜像，增量重建 NCP Compose 服务。
